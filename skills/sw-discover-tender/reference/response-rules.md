# Response CSV rules

The rules for the response CSV the client receives. Goes into every §RESP brief verbatim. Section numbers refer to the analysis file.

- **RSP-1 Columns.** The header row is the client's: every context column verbatim in the client's order and wording, then the vendor columns exactly as the client named them. Context cells are copied from the source unchanged. The skill fills only the compliance, comment and effort columns; every other vendor column (one-off cost, recurring cost, further columns) is present and empty. When the source has no vendor columns, `Vendor: Compliance`, `Vendor: Comment`, `Vendor: Effort (PD)` are appended in the RFP's language.
- **RSP-2 Rows.** Exactly the source rows in source order, one line per requirement. No row added, dropped, merged or reordered. Cells the client had prefilled are kept. Assumption and clarification sub-lines never become rows.
- **RSP-3 Compliance.** The token from the client's allowed list per `coverage-mapping.md`, derived from the row's class after accepted assumptions. A blocked row carries its likely class. `Not offered` only on a partner decision logged as `C-n`.
- **RSP-4 Comment.** Client-facing, RFP language, plain words, no internal identifiers. Order: the one-line mechanism; then every accepted assumption that names the row (its own `.a` lines and global lines) as one sentence each, introduced as "Assumption:"; then clarifications (`.c` lines, `RC-n` naming the row) introduced as "As clarified:"; then, for a row whose status names a still open non-blocking client question (`estimated, CQ-n`), "Subject to the open clarification" in plain words. Never present: proposed or rejected assumptions, PD deltas, evidence paths, agent names, low/mid/high figures, money.
- **RSP-5 Effort.** The row's PD final from section 4 after accepted assumptions, with overhead and buffer as applied in section 2, so the column sums to the Summary totals. Number with a dot decimal, rounded as in the analysis. Blocked rows: empty cell and the comment "Effort stated after clarification of <topic in plain words>". Commitment rows: 0. Service rows: their PD.
- **RSP-6 Money.** Cost cells stay empty. No currency, rate, price or budget reference anywhere in a file.
- **RSP-7 Encoding and delimiter.** UTF-8. When the input was the operator's CSV export, delimiter, quoting and BOM mirror that file. Otherwise UTF-8 with BOM, semicolon for a German RFP, comma otherwise. RFC 4180 quoting: fields containing the delimiter, a quote or a line break are quoted, quotes are doubled; line breaks inside a comment are allowed. One header row, no blank lines, no totals row, no timestamps.

Class notes for the comment, before the mechanism: `commitment` → "No development, commitment." · `service` → "Service effort, no development." · `config` → "Configuration only." · `plugin` → "Store extension, integration effort only; <extension>, <licence source>."
